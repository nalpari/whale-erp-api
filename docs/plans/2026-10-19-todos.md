## 데이터

스키마는 이미 있다: `todos` · `todo_assignees` · `todo_status_histories`, enum `TodoAssigneeType(INDIVIDUAL·ALL)` · `TodoExecutionMode(EACH·ANY_ONE)` · `TodoStatus(PENDING·IN_PROGRESS·DONE)`. 새 칸이 필요해지면 그때 마이그레이션을 만든다.

| 배정 | `todos` 행 | `todo_assignees` | `assignment_group_id` |
|---|---|---|---|
| 개인 (한 명 이상) | 직원마다 1행 | 그 직원 1행 | 여러 명이면 같은 그룹 |
| 근무지 전체 · 각자 수행 | 재직자마다 1행 | 그 직원 1행 | 같은 그룹(대상이 한 명이면 1행이라 없음) |
| 근무지 전체 · 한 명 수행 | 공유 1행 | 대상 전원 | 없음 |

- 「재직자」는 등록 시점에 그 근무지에 체결 완료(`SIGNED`) 근로계약이 있고, 가입을 마쳤고(계정 있음), 퇴직하지 않은 직원 레코드다(퇴직 예정 포함, 운영 정책 v140 PAY-16 · CTR-29, 2026-10-19 재영). 종이 계약으로 체결 완료지만 가입 전인 직원은 뺀다(2026-10-19 재영). 계약 종료일이 지났어도 상태가 체결 완료면 넣는다 — 기간 만료로 상태를 바꾸는 규칙이 없다. 개인 배정 검증 · 근무지 전체 펼치기 · 수행 임박 알림 받는 사람 · 직원 근무 앱 내 TO-DO 가 모두 이 기준을 쓴다.
- 본사 제공 동의(운영 정책 v143 ATT-30, 2026-10-19 재영): 본사 계정(BP 마스터 · BP 관리자)이 가맹 점포를 보면 동의하지 않은 직원은 직원 고르기에서 빠지고, 개인 배정이면 400, 목록의 직원 필터면 404(직원 상세와 같음)다. 목록 · 상세의 직원 이름은 가린다 — `{ staffMemberId: null, staffMemberName: null, isMasked: true }`, 이력은 `isStaffMemberMasked` · `isUnassignedStaffMemberMasked`. 그 점포에는 근무지 전체 배정만 남고, 펼치기는 동의와 상관없다.
- 한 명 수행에서 먼저 완료한 사람이 `performer_staff_member_id` 가 된다.

## API

관리자 쪽 (`@UserTypes('admin')`, 메뉴 「TO-DO 리스트 관리」 `MN000026`, 업무 범위 밖 TO-DO 는 404)

| 메서드 · 경로 | 하는 일 | 권한 |
|---|---|---|
| `GET /todos` | 목록. 필터: 근무지·상태·담당(개인/근무지 전체)·직원·수행 예정 기간·긴급. 정렬: 미완료 긴급 → 미완료 나머지 → 완료, 묶음 안은 수행 예정 일시 오름차순. 그룹은 한 줄로 묶어 보인다 | read |
| `GET /todos/assignable-staff?storeId=` | 등록의 직원 고르기. 그 근무지의 「재직자」(체결 완료 계약 · 가입 완료 · 퇴직 전)를 이름순으로, `{ items: { staffMemberId, name, phoneLast4, jobTitle }[] }`. 번호는 끝 4자리만. 근무지가 업무 범위 밖이면 404. 본사 계정이 가맹 점포를 보면 본사 제공에 동의한 직원만(운영 정책 ATT-30) | create |
| `GET /todos/:todoId` | 상세와 상태 이력, 그룹이면 직원별 상태 | read |
| `POST /todos` | 등록. 배정 그룹을 펼쳐 행을 만든다 | create |
| `PATCH /todos/:todoId` | 제목·내용·수행 예정 일시·긴급 수정. 그룹이면 그룹 전체. 배정 대상·수행 방식은 못 바꾼다 | update |
| `PATCH /todos/:todoId/status` | 관리자가 상태를 바꾼다(T-1). 그룹이면 그 행만 | update |
| `DELETE /todos/:todoId` | 대기일 때만 지운다(`is_deleted`). 그룹이면 그룹의 대기인 행만(T-2) | delete |
| `GET /staff-members/:id/todos` | 직원 상세의 TO-DO 영역(#118) | 「직원 정보 관리」 read |

직원 쪽 (`@UserTypes('account')`, 자기 직원 레코드에 배정된 것만)

| 메서드 · 경로 | 하는 일 |
|---|---|
| `GET /me/todos` | 근무지별 내 TO-DO. 체결 완료 근로계약이 있는 점포의 것만(운영 정책 CTR-29, 「재직자」 기준), 조건 밖 직원 레코드의 TO-DO 는 빼고 상태 변경도 404. 홈 카드와 근무 탭이 같이 쓴다. 공유 건은 완료됐으면 수행자 이름을 보인다(WORK-3) |
| `PATCH /me/todos/:todoId/status` | 대기 ↔ 진행 중 ↔ 완료. 공유 건은 먼저 저장된 완료만 인정하고 늦으면 409 `TODO_ALREADY_DONE` |

- 상태가 바뀔 때마다 `todo_status_histories` 에 한 줄 남긴다. 관리자는 `changed_by`, 직원은 `staff_member_id`. 긴급을 바꾸면 `is_urgent_changed`.
- 공유 완료는 읽은 상태를 조건으로 거는 `UPDATE ... WHERE status = <읽은 상태>` 로 한 번만 성공하게 한다. 완료는 늘 완료가 아닌 상태에서 바뀌므로 `status <> 'DONE'` 을 포함하고, 이력의 변경 전 상태도 맞는다.

## 수행 임박 알림 (#115)

- 배치 이름을 `BATCH_JOB` 에 더하고 `BatchLockService.runExclusive` 로 5분마다 돈다.
- 대상: 지우지 않은 대기·진행 중 TO-DO 가운데 「시간 있음: 수행 예정 일시 − 1시간 ≤ 지금」, 「날짜만: 수행 예정 날짜 09:00 ≤ 지금」이고 수행 예정 일시가 아직 지나지 않은 것(날짜만이면 그날 끝까지). 이미 보낸 것은 뺀다.
- 받는 사람: 개인·각자 수행은 그 직원, 한 명 수행은 대상 전원의 계정. 「재직자」 기준(체결 완료 계약 · 가입 완료 · 퇴직 전) 밖의 직원은 뺀다.
- `notifications`(직원 알림) + `notification_recipients` 를 만들고 `dedupe_key = todo-due-soon:<todoId>:<수행 예정 일시>:<accountId>`(T-3) 로 한 번만 보낸다. 긴급 여부를 함께 남긴다.
- 앱 푸시는 수신 설정 묶음 TO-DO 를 따른다. 실제 발송 수단(FCM 등)과 푸시 토큰 등록이 아직 없어서, `notification_deliveries` 에 발송 대기로 남기고 발송 함수는 자리만 둔다. 발송 기반은 #321 이 맡는다.
- 기본 템플릿 `PUSH_TODO_ASSIGNED` 를 `PUSH_TODO_DUE_SOON`(템플릿 이름 「TO-DO 수행 임박 알림」)으로 바꾸는 마이그레이션을 넣는다. 문구 후보: 제목 「곧 수행할 TO-DO가 있습니다」, 본문 「#{TO-DO제목} · #{수행예정일시}」.
- 배정 때는 아무 알림도 만들지 않는다.

## 상단 점포 범위 연동 (2026-10-22 재영, Plane 일감 없음)

작업 위치: 워크트리 `~/.whale-erp-worktrees/whale-erp-api/machu-picchu`, 브랜치 `cubone`(origin/main `e8f0807`). 근거: 1팀 front #88 「[공유] 상단 점포 범위 ↔ 목록 점포 필터 연동」, 기획 세션 전달.

- `GET /todos` 에 `storeIds`(고른 점포, `storeIds=1&storeIds=2` 또는 쉼표, 1000개까지)와 `storeTypes`(DIRECT · FRANCHISE)를 더한다 — 점포 목록 `ListStoresQueryDto` 와 같은 모양. 직원 근무 앱 · 직원 상세가 쓰는 `storeId` 는 그대로 두고 셋을 AND 로 건다. 업무 범위 밖 점포는 빠지고, 겹치는 점포가 없으면 0건이다.
- `storeTypes` 는 상단 범위 직영 · 가맹이라 폐점 점포를 뺀다(2026-10-22 재영, 기획 세션 리뷰). 범위 칩이 폐점을 빼므로 목록도 맞춘다. 로그인 정보의 점포는 브라우저에만 있어 front 서버가 id 를 풀 수 없으므로 api 에서 뺀다. 폐점 점포 TO-DO 는 전체 · 점포를 골라 본다.
- 주소(`scope=ALL · DIRECT · FRANCHISE · STORE:id`, `storeIds=`)를 api 조건으로 바꾸는 것은 front 서버가 한다.
- 시험: 단위(범위와의 교집합 · 유형 · AND · 0건), e2e(쉼표 · 반복 · 범위 밖 · 형식 오류 400).
