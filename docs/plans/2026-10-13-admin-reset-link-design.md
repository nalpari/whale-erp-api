# 관리자 초기화 재설정 링크 API 설계

- 날짜: 2026-10-13
- 브랜치: `charizard` (worktree `kyoto`)
- 작업: WHALEERP-172 [API] 관리자 초기화 재설정 링크
- 이 API 를 쓰는 곳: WHALEERP-173 [직원앱] 재설정 링크로 들어온 새 비밀번호 화면, WHALEERP-177 [관리자웹] 직원 비밀번호 초기화
- 상태: 설계 승인(2026-10-13 노영주). 구현 계획: `docs/plans/2026-10-13-admin-reset-link.md`

## 구현 뒤 바뀐 것 (리뷰 반영, 이 절이 아래 본문보다 앞선다)

최종 코드는 `src/auth/password-reset-link.service.ts` 이고 정리된 설명은 `okf/api/auth.md` 「관리자 초기화 reset
link」다. 아래 본문은 승인 당시 그대로 두고, 달라진 점만 여기 적는다.

- **링크 주소**: `STAFF_APP_URL` 의 **origin** + `/password-reset/link#token=…` 이다. 주소에 경로가 있으면 버린다.
- **발급 판정 6**: 잠금 안에서 1분 429 를 보기 전에 탈퇴 · 퇴직을 다시 읽고, 그 사이 바뀌었으면 409 다.
- **발급 판정 8**: 발송 실패 원인을 먼저 로그로 남긴 뒤 새 링크 행을 지운다. 지우기가 실패해도 로그를 남기고 같은
  503 이다. 발송기 계약: 실패하거나 나갔는지 모르면 던지고, 오류에 링크 · 토큰을 싣지 않는다(아래 「보낸 뒤 닫기」).
- **운영 기동**: 운영에서 `STAFF_APP_URL` 이 비면 기동은 하되 error 로그를 남긴다.
- **저장 1 · 2**: 잠금 밖에서 링크가 없음 · 닫힘 · 만료 · 탈퇴면 트랜잭션 없이 401 이다. 비밀번호 해시는 규칙을
  통과했을 때만 잠금 밖에서 만든다. 잠금 안에서 링크 행을 못 찾아도 401 이다.
- **상호 무효**: 「지금은 핀만 닫는다」는 구현 전 이야기다. 지금은 핀 · 링크 어느 쪽으로 정해도 둘 다 닫는다
  (`applyNewPassword`).
- **보낸 뒤 닫기 (api #28 리뷰, 노영주)**: 앞선 링크 · 핀은 메일이 나간 뒤 두 번째 트랜잭션(계정 행 잠금)에서
  이번 발급보다 먼저 발급된 것만 닫는다. 발송이 실패하면(타임아웃 포함) 새 링크만 지우고 아무것도 닫지 않으며
  503 「재설정 링크를 보내지 못했습니다. 잠시 뒤에 다시 보내 주세요」다. 위 「발급 판정 8」의 문구는 이것으로 바뀐다.
- **메일 연결 (api #28 리뷰)**: 발송기는 `MAIL_*` 가 있으면 `MailService` + `EMAIL_STAFF_RESET_LINK`(근무지 · 링크,
  `sentBy` = 요청 관리자), 없으면 어디서도 쓸 수 없는 Noop(발급 503 「메일 발송이 설정되지 않아…」)이다.
  `MailModule` 을 import 하지 않고 `createPasswordResetLinkSender` 가 만든다 — 메일 설정 없이도 로그인은 떠야 한다.
- **토큰은 fragment (api #28 리뷰)**: 링크는 `…/password-reset/link#token=…` 이다. fragment 는 서버로 가지 않아
  직원 앱 · BFF 접근 로그에 남지 않는다. 직원 앱 화면(173)은 `location.hash` 에서 읽는다.
- **테스트**: 직원 앱 토큰은 접속이 살아 있으면 403, sid 가 없거나 접속이 끝났으면 401 이다(e2e 가 둘 다 고정).
  동시 저장 e2e 는 다섯 번 겨루고, 잠금 뒤 다시 읽는 순서는 단위 테스트가 고정한다.

## 목적

관리자가 직원의 비밀번호 초기화를 청하면 임시 비밀번호 대신 **재설정 링크**를 직원 이메일로 보낸다. 직원은 그
링크에서 지금 비밀번호 확인 없이 새 비밀번호를 정한다. 관리자는 비밀번호를 알 수도 정할 수도 없다(ACC 정책,
WHALEERP-168). 이미 있는 본인 핀 재설정(WHALEERP-169 · 170 · 171)과 같은 규칙(비밀번호 규칙 · 접속 정리 ·
잠금 해제 · 이력)을 쓰고, 두 방식이 서로를 무효로 하는 규칙을 지킨다.

## 정해진 것

| 항목 | 결정 |
|---|---|
| 링크 주소 | `STAFF_APP_URL` + `/password-reset/link?token=…` 인 **https 주소**(2026-10-13 노영주). 지금은 직원 앱 웹에서 열리고, 앱 포장 때 같은 주소를 Universal Links · App Links 로 앱에 연결한다. 앱 스킴(`whaleerp://`)은 쓰지 않는다 — 메일 앱(Gmail 등)이 막거나 지우고, 앱이 없는 기기에서 스토어로 보낼 수 없다 |
| 직원 쪽 경로 | 링크 전용 경로 두 개(A안, 2026-10-13 노영주). 핀 경로 `POST /auth/account/password-reset` 에 섞지 않는다 |
| 관리자 응답 | **201 `{ issuedAt, expiresAt }`**(2026-10-13 노영주). WHALEERP-172 완료 조건의 「성공 204」를 바꾼다 — WHALEERP-177 이 「보낸 뒤 발송 시각과 기한을 보인다」를 따로 묻지 않고 그리게 하려고 |
| 링크 수명 | 24시간, 한 번만. 새 비밀번호를 실제로 정한 순간 닫힌다. 열거나 확인만 해서는 닫히지 않는다(메일 보안 스캐너가 미리 열어도 소진되지 않게) |
| 토큰 | 32바이트 무작위 값(base64url). DB 에는 sha256 해시만(`password_reset_links.token_hash`, 고유) |
| 상호 무효 | 관리자가 링크를 새로 보내면 앞선 링크와 핀이 모두 닫힌다. 본인 핀 요청은 링크를 닫지 않는다. 링크 · 핀 어느 쪽으로든 새 비밀번호를 정하면 남은 링크와 핀을 모두 닫는다(WHALEERP-172, 2026-10-08) |
| 메일 발송 | 핀과 같은 **발송기 자리** `PasswordResetLinkSender` 에 지금은 아무것도 보내지 않는 Noop 을 꽂는다(2026-10-13 노영주). `MailModule` 은 import 되는 순간 `MAIL_*` 가 비면 기동을 멈추고 지금 어느 환경에도 그 값이 없어, 바로 쓰면 모든 api 가 뜨지 않는다. Noop 은 운영에서 「쓸 수 없음」(발송 503), 그 밖에서는 「보낸 것으로」 답한다(핀 발송기와 같다). 핀 · 링크 발송기를 `MailService`(템플릿 `EMAIL_STAFF_RESET_LINK`)에 함께 잇는 일은 팀이 `MAIL_*` 설정을 정한 뒤 따로 한다 |
| 무효 사유 | 저장하지 않는다. 만료 · 사용 · 대체를 가르지 않고 같은 문구로 답한다 |
| 마이그레이션 | 없다. `password_reset_links` · `account_change_histories.requested_by` · `AccountChangeChannel.ADMIN_RESET` 는 이미 있다 |

## API

### 1. 관리자: 링크 보내기

`POST /staff-members/:staffMemberId/password-reset-links` — 관리자 웹 전용(`@UserTypes('admin')`). 본문 없음.

판정 순서:

1. 경로 ID 를 읽는다. 정수 범위(`1..2147483647`) 밖이면 DB 에 묻기 전에 404.
2. 관리 범위를 본다(`AdminScopeService.canManageStaffMember`, 퇴직 처리와 같다). 범위 밖 · 없는 직원 · 본사 역할에게 가린
   직원(`hidesPersonalData`)은 모두 같은 404 — 403 을 주면 그 ID 의 직원이 있다는 것이 드러난다.
3. 직원 레코드 상태: 가입 전(`staff_members.account_id` 가 비었음) 409, 퇴직(`employment_status = RETIRED`) 409.
   퇴직 예정(재직이고 퇴직일만 있음)은 보낼 수 있다.
4. 계정 상태: 탈퇴(`accounts.status = WITHDRAWN`) 409.
5. `STAFF_APP_URL` 이 비었거나 발송기가 쓸 수 없으면(`isAvailable() === false`) 503(보낼 수 없다). 계정을 찾기 전이 아니어도 된다 — 관리자 경로라 응답이
   계정 유무로 갈려도 드러날 것이 없다.
6. 한 트랜잭션: 계정 행을 잠근다(`SELECT … FOR UPDATE`). 같은 계정에 1분 안에 낸 링크가 있으면 429(하루 제한 없음).
   앞선 열린 링크(`closed_at` 채움)와 열린 핀(`used_at` 채움)을 닫고, 새 링크를 저장한다
   (`account_id` · `token_hash` · `issued_at` · `expires_at = issued_at + 24h` · `requested_by = 관리자 계정 ID`).
7. 커밋 뒤 발송기로 보낸다 — `PasswordResetLinkSender.send(대상 계정, { storeName, link, expiresAt, requestedBy })`.
   메일 구현이 꽂히면 템플릿 `EMAIL_STAFF_RESET_LINK`, 변수 `근무지`(그 직원 레코드의 점포 이름) · `링크`,
   `maskedVariables: ['링크']`(토큰이 곧 비밀번호를 바꿀 권한이라 `mail_send_logs` 에 원문을 남기지 않는다),
   `sentBy = 관리자 계정 ID` 로 보낸다. 지금 Noop 은 토큰 · 링크를 로그에도 남기지 않는다.
   관리자 경로라 핀과 달리 발송을 기다린다 — 실패를 관리자에게 알려야 하고, 응답 시간으로 드러날 것이 없다.
8. 메일이 실패하면 방금 만든 링크 행을 지우고 503. 관리자가 바로 다시 보낼 수 있게 1분 제한에 걸리지 않는다. 6에서
   닫은 앞선 링크 · 핀은 되살리지 않는다 — 새로 보내려던 상황이라 잃는 것이 없다.
9. 201 `{ issuedAt, expiresAt }`.

응답 정리: 201 성공 · 404 범위 밖 · 없는 직원 · 가린 직원 · 409 가입 전 · 퇴직 · 탈퇴 · 429 같은 계정 1분 안 재요청 ·
503 링크 주소 없음 · 발송기 쓸 수 없음 · 발송 실패. 409 는 사유를 메시지로 가른다(관리자에게는 숨길 것이 없다).

계정은 여러 BP 가 함께 쓰는 비밀번호 하나라 다른 BP 로그인에도 적용된다 — 이 안내는 WHALEERP-177 의 확인창 몫이다.

### 2. 직원: 링크 확인

`POST /auth/account/password-reset-links/verify` `{ token }` — 로그인 없이(`@Public()`).

- 쓸 수 있으면 204. 쓸 수 있다 = 그 해시의 행이 있고 · `closed_at` 이 비었고 · `expires_at > 지금` 이고 · 계정이 탈퇴가 아니다.
- 아니면 사유를 가리지 않고 같은 문구의 401 — 「쓸 수 없는 링크입니다. 관리자에게 다시 청하거나 비밀번호 찾기로 인증번호를
  받아 다시 정해 주세요」(WHALEERP-172 「관리자에게 다시 청하거나 본인 핀으로 하도록 안내」).
- 아무것도 바꾸지 않는다. 화면을 열 때 무효한 링크 안내를 먼저 보이려고 쓴다.

### 3. 직원: 새 비밀번호 저장

`POST /auth/account/password-reset-links/reset` `{ token, newPassword }` — 로그인 없이(`@Public()`).

1. 토큰 해시로 링크를 찾는다. 없으면 401(2와 같은 문구).
2. 비밀번호 해시(scrypt)는 잠금 밖에서 미리 만든다 — 잠금 안에서 30ms 씩 줄 서지 않게(핀 저장과 같다).
3. 한 트랜잭션: 계정 행을 잠그고 링크를 다시 읽는다. 쓸 수 없으면(그 사이 닫힘 · 만료 · 탈퇴) 401.
4. 쓸 수 있는데 새 비밀번호가 규칙(WHALEERP-192, `validateNewPassword`)에 어긋나면 400 과 사유. 링크는 닫지 않는다 —
   그 자리에서 다시 넣는다(핀과 같다). 규칙 검사는 링크가 쓸 수 있다는 것을 잠금 안에서 확인한 뒤에 답한다 — 닫힌 링크에
   「링크는 맞고 비밀번호가 틀렸다」고 답하지 않게.
5. 성공(204): 아래 「새 비밀번호 적용」을 같은 트랜잭션에서 한다. 변경 경로는 `ADMIN_RESET`, 요청 관리자는 링크의
   `requested_by`.

### 새 비밀번호 적용 (핀 · 링크 공통)

핀 저장(`PasswordResetService.resetPassword`)과 링크 저장이 같은 함수를 쓴다. 한 트랜잭션 안에서:

- 비밀번호 해시를 바꾼다.
- 그 계정의 열린 링크를 모두 닫고(`closed_at`), 열린 핀을 모두 닫는다(`used_at`). **핀 저장이 링크를 닫는 것은 새로 더하는
  동작이다** — 지금은 핀만 닫는다.
- 모든 기기의 접속을 끊는다(`AuthSessionService.revokeAll`, 트랜잭션 클라이언트로).
- 로그인 실패 횟수와 잠금을 지운다.
- 변경 이력(`account_change_histories`): `field = PASSWORD`, 값 없음, `channel = PIN_RESET | ADMIN_RESET`,
  `requested_by` = 링크면 요청 관리자 · 핀이면 비움.

본인 핀 요청(`requestPin`)은 링크를 닫지 않는다 — 핀 요청은 이메일만 알면 누구나 보낼 수 있어서, 닫으면 남이 관리자
조치를 무력화할 수 있다.

## 요청 제한

- 직원 쪽 두 경로는 로그인 · 핀 경로와 같은 `ThrottlerGuard` 두 축(IP · 계정)을 건다. 계정 축은 본문 `token` 의 sha256 으로
  센다(`throttle.ts` 의 `accountTracker` 에 한 갈래 추가 — 갱신 토큰과 같은 방식, 저장소에 원문이 남지 않게).
- 관리자 경로는 따로 걸지 않는다. 로그인한 관리자만 부르고 같은 계정 1분 제한이 있다.

## 설정

- `STAFF_APP_URL` — 직원 앱 주소(예: `https://staff.whale-erp.com`). `.env.example` 에 더한다.
  - 운영(`APP_ENV=prod`)에서는 https 만 받는다. 아니면 기동 때 멈춘다(설정 실수를 첫 발송 때가 아니라 배포 때 알게).
  - 비었으면 기동은 하고 발송만 503 이다 — 메일 주소 설정 없이도 로그인은 떠야 한다(핀 발송기와 같은 생각).
  - 링크는 `new URL('/password-reset/link', STAFF_APP_URL)` 에 `token` 을 쿼리로 붙여 만든다(경로 · 끝 `/` 실수 방지).

## 테스트

TDD. 단위는 `src/auth/*.spec.ts`, e2e 는 일회용 Postgres(`test/*.e2e-spec.ts`).

- 단위(서비스 규칙): 404 · 409 세 가지 · 429 판정, 발급 때 앞선 링크 · 핀 닫기, 메일 실패 때 행 지우고 503, 링크 주소 없음
  503, 확인 401 경우들, 저장 401 · 400(규칙 위반 때 닫지 않음) · 성공 때 링크 · 핀 모두 닫기 · 세션 끊기 · 잠금 해제 ·
  이력(`ADMIN_RESET` · 요청 관리자), 핀 저장이 링크도 닫는지, 핀 요청은 링크를 닫지 않는지, 토큰 원문이 저장 · 로그되지
  않는지.
- e2e(실제 DB, 메일은 가짜 발송기로 받아 링크의 토큰을 꺼냄):
  - 관리자 발송 → 확인 204 → 저장 204 → 새 비밀번호로 로그인, 다른 기기 접속 끊김
  - 범위 밖 404 · 직원 앱 토큰 403 · 가입 전 · 퇴직 · 탈퇴 409 · 1분 안 재요청 429 · 응답 201 의 시각
  - 링크 두 번 쓰기 401 · 만료 401 · 새 링크로 대체된 앞 링크 401 · 규칙 위반 400 뒤 같은 링크로 성공
  - 관리자 발송이 열린 핀을 닫음 · 핀 요청은 링크를 닫지 않음 · 핀으로 저장하면 링크가 닫힘
  - 같은 링크로 저장을 동시에 두 번 보내면 하나만 성공
- 직원 계정 경로 허용 목록(`test/account-status-policy.e2e-spec.ts`, WHALEERP-168)에 직원 쪽 두 경로를 더한다 — 둘 다
  비밀번호를 보여 주거나 대신 로그인시키지 않는다(관리자는 링크를 받지 못한다).

## 남는 것 · 바깥 의존

- **관리자 로그인(1팀) 전이다.** api 는 관리자 토큰을 검사할 수 있지만 발급하는 로그인이 없다. 테스트는 `JWT_SECRET` 으로
  만든 관리자 토큰으로 한다. 토큰 모양(`sub` = `admin_accounts.admin_account_id`)은 1팀과 맞춰 둔 것을 따른다.
- **WHALEERP-173** 은 이 API 로 웹 화면을 만들 수 있다. 앱 딥링크 · 스토어 이동은 앱 포장 결정 뒤다.
- **WHALEERP-177** 은 직원 상세(WHALEERP-184)의 「비밀번호 초기화」 버튼을 이 API 에 붙인다. 실제로 쓰려면 관리자 로그인이
  있어야 한다.
- WHALEERP-172 완료 조건의 「성공 204」→「201 과 발송 시각 · 기한」은 Manyfast · Plane 반영을 재영님께 요청한다.
