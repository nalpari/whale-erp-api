# 내부 납품 산출물: 완료보고서(워드)

근거: 2026-11-09 기획 세션 지시. 산출물 9번. 템플릿과 공통 코드는 `2026-11-05-deliverables-policy-userflow.md` 와 같이 쓴다.

## 정해진 것

- 문서 번호 `WHALE-RPT`, 문서 이름 완료보고서, 작성자 인터플러그, 버전 1.0. `revisions.json` 에 넣는다.
- 생성기 `deliverables/build_completion_report.py`, 자체 검사 `deliverables/test_build_completion_report.py`.
- 전체 영역을 싣는다. 숫자는 손으로 적지 않고 다른 생성기의 원본과 셈 함수에서 읽는다. 값을 못 읽거나 합이 맞지 않으면 멈춘다.

## 절과 원본

| 절 | 내용 | 원본 |
|---|---|---|
| 1. 프로젝트 개요 | 영역별 설명 첫 문장, 사용 기기, 대상 역할 | `manyfast.json` 요구사항 · 기기, 운영 정책 권한 장의 역할 표 |
| 2. 수행 범위 | 영역별 화면 수와 사용 메뉴 수, 제외 범위 | `screens/areas`, `menus.json`, 운영 정책 「1차 범위에서 제외」 |
| 3. 산출물 목록 | 문서 번호 · 산출물 · 형식 · 버전 · 기준 9종 | `revisions.json`, 각 원본의 커밋 · 버전 |
| 4. 결과 요약 | 요구사항 · 기능 · 명세, 메뉴, 테이블 · 컬럼, API, 규칙, 화면, 흐름 | 각 생성기의 셈 함수 |
| 5. 테스트 결과 요약 | 저장소 · 종류별 합계, 실패 · 제외 건수와 사유 | `test_results.json` |
| 6. 잔여 사항 | 외부 검토, 2차로 미룬 항목, 테스트 실패 처리 계획 | 운영 정책 「아직 정해지지 않은 것」, `test_results.json` |

- 스냅숏에는 PRD 가 없어 서비스 목적은 요구사항 영역의 설명 첫 문장으로 대신한다. 대상은 운영 정책의 역할 표로 적는다.
- 사용 메뉴는 `ACTIVE` 이고 지우지 않은 메뉴다. 영역 표의 합이 메뉴 스냅숏의 사용 메뉴 수와 다르면 멈춘다.
- 실패 · 제외 건수는 실패한 테스트, 테스트 밖 실패, 린트 오류를 하나씩 센다. 표의 합이 원본 목록 수와 다르면 멈춘다.
- 린트 · 타입 오류의 사유는 규칙 이름까지만 적는다. 오류 문장 전체는 테스트 결과서에 있다.

## 멈추는 경우

- 메뉴 스냅숏의 마지막 마이그레이션이 저장소의 마지막 것과 다를 때. `--draft` 를 주면 넘어가고 경고를 찍으며 파일 이름에 `_초안` 을 붙인다. 납품본은 `--draft` 없이 만든다.
- 테스트 요약의 실패 · 제외 칸과 목록이 어긋날 때(단위 · e2e 는 실패 + 테스트 밖 실패, 린트는 실패 파일 수, 타입은 유무).
- `revisions.json` 문서가 9종이 아닐 때, 각 생성기의 셈이 멈출 때(API 문서와 소스가 어긋남 등).
- 표지 · 개정 이력 · 머리글 · 본문 · 표의 글자에 쟁점 번호, 「쟁점」, 팀 표시, 팀원 실명, 일감 · PR 번호, 내부 도구 이름, 미결 메모, 실제 이메일 · 휴대전화번호, 저장소 경로, 자리표시자, 옛 근로계약 상태 이름이 남을 때.

## 넣지 않는 것

일정, 투입 인력, 비용, 성과 평가, 고객 확인 · 검수 결과, 수동 테스트 결과. 근거 문서가 없다.

## 실행

```bash
.venv/bin/python build_completion_report.py --version 1.0
.venv/bin/python test_build_completion_report.py
```

전체 재생성 때는 다른 원본을 모두 갱신한 뒤 맨 마지막에 돌린다.
