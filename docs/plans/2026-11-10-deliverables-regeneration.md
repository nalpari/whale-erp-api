# 내부 납품 산출물: 전체 재생성 (운영 정책 v275)

근거: 2026-11-09 · 11-10 기획 세션 지시. 근로계약 상태 이름 변경과 유저플로우 정리가 머지된 뒤 납품 문서 9종을 다시 만든다.

## 순서

1. 원본 사본을 갱신해 커밋한다: `menus.json`, 운영 정책 사본(v275), 유저플로우 사본, 화면설계서 이미지 · 설명 표, 테스트 결과(`--run`), `openapi.json`이 코드와 어긋나면 재생성본.
2. 깨끗한 작업 트리에서 8종을 만든다.
3. 맨 마지막에 완료보고서를 `--draft` 없이 만든다.

## 하지 않는 것

- 제품 코드와 시험 코드 수정. 원본 사본 · 생성기 교정표 · 결과 파일만 바꾼다.
- 점검에 걸린 내용을 지어 고치는 일. 교정표에 없는 표현이 나오면 보고한다.
- Manyfast 스냅숏 갱신. 지시 범위 밖이라 `manyfast.json` 은 2026-11-05 기준 그대로 둔다.

## 엑셀 3종 정리 (2026-11-10 재영 승인)

요구사항정의서 · 테이블정의서 · API 명세는 원문을 옮기는 문서라, 원문은 두고 `deliverables/sheet_clean.py` 로 생성 때 정리한다.

- 실명 · 「쟁점」 · 쟁점 번호 · 팀 표시 · 일감 번호를 지우고 어색해진 괄호를 정리한다. 남으면 생성을 멈춘다. 요구사항정의서의 Plane 칸은 없애고(재영 결정), 추적용 ID 칸만 그대로 둔다.
- 옛 상태 이름은 문맥이 근로계약 상태로 정해지는 곳만 8종 표준 이름으로 바꾼다. 동의 거부 · 소속 추가 거절 · 초대 만료 · 공지 임시저장은 두고, 받침에 따라 조사도 맞춘다.
- 팀 표시가 든 문장은 낱말을 지우지 않고 `FIXES` 로 문장 단위로 고친다. 스키마 · 코드에 남은 연결 보류와 본인인증 칸의 설명에는 「1차에서 쓰지 않는 값」을 붙인다.
- 없앤 개념(본인인증, 가입 연결 · 연결 보류)은 지금 기능처럼 적힌 문장만 생성기의 `FIXES` 로 고친다. 1차 범위 밖 설명은 두고, 판단이 갈리는 칸은 `out/정리 검토 목록_*.tsv` 로 낸다.
- 자체 검사 `test_sheet_clean.py`. 각 문서의 본문 대조 검사는 정리 뒤의 글을 기준으로 한다.

## 화면설계서 버튼 이름 수정 (2026-11-10 재영 승인)

front #247 로 급여명세서 경고 띠 버튼이 [출퇴근 보정]에서 [출퇴근 기록 확인]으로 바뀌었다. 화면설계서의 급여명세서 검토 설명 표 2곳만 고치고 화면설계서만 다시 낸다.

- 고치는 곳: `sources/screens/areas/03_admin_staff.json` 의 구성 요소 이름과 동작 설명. 관리자 기능을 가리키는 「출퇴근 보정」은 그대로 둔다.
- 이미지는 front #248 로 데모를 고친 뒤 다시 찍는다(재영 결정). 찍는 기준은 front main 51b51974 이고, 이미지 · `visible_text.json` · `SOURCE.json` 을 함께 갱신한다. 생성기의 글자 치환(`TEXT_FIXES`)은 쓰지 않는다.
- 전체를 다시 찍되 글자가 같은 이미지의 렌더링 잡음은 이전 파일로 되돌려 SCR-ADM-019 만 바꾼다.
- 찍은 기준이 바뀌므로 완료보고서를 다시 낸다. 납품본 뒤에 api #268 이 들어와 API 명세의 기준이 달라졌으므로 API 명세도 다시 낸다(재영 결정, 값은 같아야 한다). 다른 6종은 다시 내지 않는다.
- 검증: 납품본과 새 파일의 XML · 이미지를 비교해 달라진 것이 이 2곳뿐인지 보고, `out/manifest.json` 의 해시를 새 파일과 대조한다.

## 운영 정책 v276 반영 (2026-11-10 재영 결정)

운영 정책 SCP-01 · 02 · 06 문구가 바뀌어 운영 정책 사본을 v276으로 갈고 운영 정책서와 완료보고서만 다시 낸다.

- 사본은 v275(2026-11-10 복사)였고, 원본과의 차이는 규칙 3줄뿐임을 복사 전에 확인했다. 규칙 수 221은 그대로다.
- 고치는 곳: `sources/운영정책.html`, `build_policy.py` 의 `SOURCE_VERSION`. 정책서의 「원본 운영 정책 v…」 표기도 이 값을 따라 v276이 된다.
- 다른 7종은 다시 내지 않는다. 완료보고서는 운영 정책 기준 칸이 달라져 함께 낸다.
- 검증: 납품본과 새 파일의 문단 · 표를 비교해 정책서는 SCP 3개 문단과 원본 버전 표기, 완료보고서는 기준 칸만 달라졌는지 본다. 납품본 `out/` 은 건드리지 않고 작업 트리의 복사본에서 만든다.

### 요구사항정의서 · 유저플로우의 SCP-06 반영 (2026-11-10 재영 결정)

옛 SCP-06 문장이 두 문서에 남아 있어 함께 맞춘다.

- 요구사항정의서: Manyfast 스냅숏을 새로 받는다. 지난 스냅숏(2026-11-05)과 달라진 곳은 「로그인 후 개인화 홈」의 동작 · 비즈니스 규칙 두 칸뿐임을 재생성 전에 확인했다.
- 유저플로우: front `docs/flow/entry-home` 을 PR로 고쳐 머지한 뒤 `build_userflow.py --snapshot` 으로 사본을 뜬다. 2026-11-11 front 1447f25b · staff 7c4fc413 에서 떴고, 바뀐 파일은 entry-home 둘뿐이다. staff 는 커밋만 앞으로 갔고 흐름 파일은 같다.
- 완료보고서는 기준 칸이 바뀌어 마지막에 다시 낸다. 화면설계서는 front 다음 변경이 머지될 때까지 다시 내지 않는다.

### 화면설계서: 일괄 저장 · 기간 출·퇴근 기록 · 신고 정보 (2026-11-11 재영 결정)

front #251(일괄 저장 문구) · #252(급여명세서에서 연 기간 기록)는 앱만 고쳐서, 데모를 앱에 맞춘 front #258(127fbcf2)을 머지한 뒤 그 화면만 다시 찍는다. staff #69(신고 정보 안내, 운영 정책 TAX-07)도 함께 넣는다.

- 찍기 기준: 관리자 웹은 51b51974 그대로 둔다. 그 뒤 들어온 시설물 · 장비 · 수리 이력 화면과 비로그인 개편은 넣지 않는다. 바뀐 화면만 127fbcf2에서 찍고, 직원 근무 앱은 25b25eb5에서 찍는다.
- 생성기: `build_screens.py --capture` 에 `--ref 저장소=커밋`(기준 커밋 고정)과 `--overlay 커밋`(그 커밋이 바꾼 데모 파일만 관리자 웹 기준 위에 덮음)을 더한다. 덮은 커밋은 `SOURCE.json` 에 남는다. 기준 칸은 「관리자 웹 51b51974(일부 화면 127fbcf2) · 직원 근무 앱 25b25eb5」처럼 화면별 기준이 다르다는 것을 적는다.
- 새 화면 「기간 출·퇴근 기록」을 출·퇴근 현황 조회 바로 뒤 SCR-ADM-022로 넣고, 그 뒤 번호를 하나씩 민다(재영 결정). 화면 112 → 113.
- 설명 표: 일괄 저장(SCR-ADM-013)은 #251 문구로, 급여명세서 검토의 「출퇴근 기록 확인」은 기간 출·퇴근 기록으로 가는 것으로, 신고 정보 화면은 TAX-07 문구로 고친다.
- 이미지: 전체를 다시 찍되, 보이는 글자가 납품본과 같은 화면은 이전 이미지로 되돌려 렌더링 잡음을 없앤다.
- 유저플로우는 흐름 파일 변경이 없어 다시 내지 않는다. 완료보고서는 화면설계서 기준 칸이 바뀌어 다시 낸다.
