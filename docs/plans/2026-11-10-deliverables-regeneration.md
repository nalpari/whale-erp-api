# 내부 납품 산출물: 전체 재생성 (운영 정책 v275)

근거: 2026-11-09 · 11-10 기획 세션 지시. 근로계약 상태 이름 변경과 유저플로우 정리가 머지된 뒤 납품 문서 9종을 다시 만든다.

## 순서

1. 원본 사본을 갱신해 커밋한다: `menus.json`, 운영 정책 사본(v275), 유저플로우 사본, 화면설계서 이미지 · 설명 표, 테스트 결과(`--run`), `openapi.json`이 코드와 어긋나면 재생성본.
2. 깨끗한 작업 트리에서 8종을 만든다.
3. 맨 마지막에 완료보고서를 `--draft` 없이 만든다.

## 하지 않는 것

- 제품 코드와 시험 코드 수정. 원본 사본 · 생성기 교정표 · 결과 파일만 바꾼다.
- 점검에 걸린 내용을 지어 고치는 일. 교정표에 없는 표현이 나오면 보고한다.
- Manyfast 스냅숏 갱신. 지시 범위 밖이라 `manyfast.json` 은 2026-11-05 기준 그대로 둔다.

## 엑셀 3종 정리 (2026-11-10 재영 승인)

요구사항정의서 · 테이블정의서 · API 명세는 원문을 옮기는 문서라, 원문은 두고 `deliverables/sheet_clean.py` 로 생성 때 정리한다.

- 실명 · 「쟁점」 · 쟁점 번호 · 팀 표시 · 일감 번호를 지우고 어색해진 괄호를 정리한다. 남으면 생성을 멈춘다. 요구사항정의서의 Plane 칸은 없애고(재영 결정), 추적용 ID 칸만 그대로 둔다.
- 옛 상태 이름은 문맥이 근로계약 상태로 정해지는 곳만 8종 표준 이름으로 바꾼다. 동의 거부 · 소속 추가 거절 · 초대 만료 · 공지 임시저장은 두고, 받침에 따라 조사도 맞춘다.
- 팀 표시가 든 문장은 낱말을 지우지 않고 `FIXES` 로 문장 단위로 고친다. 스키마 · 코드에 남은 연결 보류와 본인인증 칸의 설명에는 「1차에서 쓰지 않는 값」을 붙인다.
- 없앤 개념(본인인증, 가입 연결 · 연결 보류)은 지금 기능처럼 적힌 문장만 생성기의 `FIXES` 로 고친다. 1차 범위 밖 설명은 두고, 판단이 갈리는 칸은 `out/정리 검토 목록_*.tsv` 로 낸다.
- 자체 검사 `test_sheet_clean.py`. 각 문서의 본문 대조 검사는 정리 뒤의 글을 기준으로 한다.

## 화면설계서 버튼 이름 수정 (2026-11-10 재영 승인)

front #247 로 급여명세서 경고 띠 버튼이 [출퇴근 보정]에서 [출퇴근 기록 확인]으로 바뀌었다. 화면설계서의 급여명세서 검토 설명 표 2곳만 고치고 화면설계서만 다시 낸다.

- 고치는 곳: `sources/screens/areas/03_admin_staff.json` 의 구성 요소 이름과 동작 설명. 관리자 기능을 가리키는 「출퇴근 보정」은 그대로 둔다.
- 이미지는 다시 찍지 않는다. #247 은 `docs/demo` 를 바꾸지 않아 데모와 이미지에 옛 버튼 이름이 남는다. `visible_text.json` 은 찍을 때 보인 글자의 기록이라 이미지와 함께만 바꾼다.
- 다른 8종과 완료보고서는 다시 내지 않는다. 화면설계서의 기준(`SOURCE.json`)이 그대로라 완료보고서 내용에 영향이 없다.
- 검증: 납품본과 새 파일의 XML · 이미지를 비교해 달라진 것이 이 2곳뿐인지 보고, `out/manifest.json` 의 해시를 새 파일과 대조한다.
