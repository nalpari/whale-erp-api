# 내부 납품 산출물: 화면설계서(워드)

근거: 2026-11-09 기획 세션 지시(재영 승인). 산출물 7번. 템플릿 · 공통 코드는 `2026-11-05-deliverables-policy-userflow.md` 와 같이 쓴다. 이 문서는 1단계(화면 목록 · 캡처 · 생성기 골격) 범위이고, 설명 표 내용은 다음 단계에서 채운다.

## 정해진 것

- 문서 번호 `WHALE-SCR-1.0`, 문서 이름 화면설계서, 작성자 인터플러그. `revisions.json` 에 넣는다.
- 생성기 `deliverables/build_screens.py`. `common.py` 의 `open_docx` · `heading` · `para` · `table` · `save_docx` 를 쓴다. 내부 납품용이라 가볍게 간다.
- 범위는 전체 영역(1팀 화면 포함)이다.

## 원본과 사본

- 원본: 관리자 웹은 `whale-erp-front docs/demo`, 직원 근무 앱은 `whale-erp-staff docs/demo` 의 HTML 이다. 두 저장소의 origin/main 을 `git archive` 로 임시 폴더에 풀어 `file://` 로 연다. 체크아웃은 바꾸지 않는다.
- 사본: HTML 은 저장소에 넣지 않는다(front 만 33MB). 찍은 JPEG 만 `sources/screens/img/` 에 커밋 대상으로 두고, 원본 커밋 해시를 `sources/screens/SOURCE.json` 에 적는다. `--capture` 로 다시 찍는다.
- `out/screens_visible_text.json`: 화면마다 찍을 때의 보이는 글자(DOM innerText + 자리표시 글자)를 남긴다. 입력값은 저장하지 않고, 커밋하지 않는다. 입력값(비밀번호 칸 제외)까지 포함한 이미지 글자 점검은 찍을 때 끝나서 납품 점검에 이 파일이 꼭 필요하지 않다. 파일이 있으면 생성할 때 한 번 더 점검한다.
- 뺀 것: `_check/`, `kit-*`, `build.mjs`, `src/`, `assets/`, 데모 목록(`index.html`).

## 캡처

- 뷰포트: 관리자 웹 1440×900, 배율 1. 직원 근무 앱 390×844, 배율 2. 비로그인 화면 1720×900, 배율 1. JPEG 품질 72.
- **데모 프레임의 최소 폭 1720px 은 찍을 때 풀어 준다.** 관리자 웹 데모는 `min-w-[1720px]` 라 1440 뷰포트에서 표 오른쪽과 슬라이드 패널이 잘린다. 지시받은 1440 폭을 지키려고 관리자 웹만 찍기 전에 이 최소 폭을 0으로 덮는다(원본은 고치지 않음). 비로그인 화면은 고정 폭 디자인이라 덮지 않고 1720 폭으로 찍는다.
- 관리자 웹은 본문이 안쪽 스크롤이라 그대로 찍으면 잘린다. 안쪽 스크롤 높이만큼 뷰포트를 늘려서 찍는다(최대 +1800px).
- 긴 화면은 잘라서 여러 장으로 싣는다(한 장 높이: 폭 1440~1720 은 1900px, 직원 근무 앱은 1100px). 페이지 한 쪽에 들어가게 하려는 것이다. 이미지 파일 이름은 `<화면 번호>.jpg`, 다음 장은 `<화면 번호>-2.jpg`.
- 직원 근무 앱 데모는 파일 하나에 `data-state` 블록 여러 개가 있고 주소 해시로 바뀐다(`#sign` 등). `staff.js` 가 상태를 옮길 때 블록을 되그리므로 해시를 바꾼 뒤에 가리기 · 글자 치환을 한다.
- 직원 근무 앱에서 바텀시트가 열린 상태(위치정보 동의 · 수정 요청 등)는 시트가 화면 아래에 붙어 있어 전체 쪽이 아니라 뷰포트만 찍는다.
- 찍다 실패하거나 점검에 걸리면 빈 칸을 두지 않고 멈춘다.

## 데이터 파일

- `sources/screens/areas/NN_<영역>.json` 영역별 파일. 설명 작성을 나누어 맡기 위해 파일을 나눈다. 파일 이름 순서가 문서 순서다.
- 형식: `{"client": "admin|staff|public", "area": "영역 이름", "screens": [...]}`
- 화면 항목: `id`(SCR-ADM-001 · SCR-APP-001 · SCR-PUB-001), `name`, `menuCode`(메뉴 테이블 항목이면) 또는 `menu`(메뉴 밖 · 하단 탭), `route`(앱 경로, 찾지 못하면 null), `routeNote`(슬라이드 패널 · 못 찾음 등 표시), `demo`(`{"file", "state"}`), `images`(캡처가 채움), `rows`(설명 행 배열).
- `id` · `rows` 는 사람이 채우고, `images` 는 `--capture` 가 다시 쓴다(rows 는 건드리지 않는다).
- 설명 행: `{"zone": "구역", "element": "구성 요소", "action": "동작", "policies": ["ACC-11"]}`. `policies` 는 규칙 번호만 적고 문서에는 「운영 정책 ACC-11」로 나간다. 운영정책.html 에 없는 번호면 멈춘다.
- `sources/screens/excluded.json`: 뺀 데모 페이지 · 상태와 이유. 데모의 모든 페이지 · 상태는 화면이거나 이 목록에 있어야 한다(없으면 멈춘다).

## 구성

- 장: 관리자 웹 → 직원 근무 앱 → 비로그인 화면. 절: 영역. 관리자 웹 영역 순서는 메뉴구조도(서비스 순 · 정렬 순서). 메뉴에 없는 공통 화면(홈 · 마이페이지 등)은 관리자 웹 맨 앞, 메뉴에 없는 알림 템플릿 관리는 플랫폼 뒤에 둔다.
- 직원 근무 앱 메뉴는 DB 에 없다. 데모의 묶음(로그인·가입, 홈·근무·출퇴근, 계약·신고 정보, 급여·알림·내 정보)과 하단 탭(홈 · 근무 · 출퇴근 · 급여 · 내 정보)을 메뉴 위치로 쓴다.
- 화면마다: 제목 3(`화면 번호 화면 이름`), 정보 표(화면 번호 · 화면 이름 · 메뉴 위치 · 경로), 이미지, 설명 표(구역 · 구성 요소 · 동작 · 관련 운영 정책 번호).
- 대표 화면 위주로 싣는다. 빈 목록 · 오류 · 잠김 등의 상태는 빼고, 동작 설명에 꼭 필요한 것만 둔다(날인 요청 팝업, 위치정보 동의, 수정 요청 등).

## 가리기 · 납품본 점검

- 찍기 전 DOM 에서만 고친다. 원본은 고치지 않는다.
  - 직원 근무 앱의 상태 도구(`details:has([data-demo-pick])`)를 숨긴다.
  - 직원 근무 앱의 하단 탭(`sticky bottom-0`)은 전체 쪽을 찍으면 본문 중간에 겹치므로 흐름 배치로 바꿔 본문 맨 아래에 둔다.
  - `DEMO_BUTTONS`: 데모 상태로 옮겨 가기만 하는 버튼(「만료된 초대면?」 등)을 글자로 찾아 숨긴다. 못 찾으면 멈춘다.
  - `TEXT_FIXES`: 쟁점 표시 · 안내 문구를 지운다. 원문에서 못 찾으면 멈춘다(원본이 바뀌었는지 확인).
  - 모든 글자에 `common.safe` 를 건다: 이메일은 `@example.com`, 휴대전화번호는 `010-1234-5678` 로 바뀐다. 데모의 예시 값이 실제 값일 가능성을 없애려는 것이고, 다른 산출물과 같은 방식이다.
- 생성을 멈추는 조건(문서 글자와 이미지 글자 모두): 목업 쟁점 번호, 「쟁점」, 팀 표시, 팀원 실명(`common.TEAM_NAMES`), 일감 · PR 번호(`common.INTERNAL`), 내부 도구 이름, 저장소 경로, 미결 메모(`미정` 등), 실제 이메일 · 휴대전화번호. 운영 정책 번호는 「운영 정책」을 붙인 것만 통과한다.
- 업무어는 통과 목록(`MEMO_ALLOW`)에 적는다: 「시간 미정」(수행 예정 일시), 급여명세서 상태 「검토 중」 등.

## 자체 점검

- 메뉴 수 대비 화면 수를 출력한다. 사용 중인 말단 메뉴에 화면이 없으면 멈춘다.
- 이미지 수와 파일이 맞는지, 빠진 화면 0. 설명 표가 빈 화면 0(`--draft` 일 때만 건너뛴다).
- `test_build_screens.py`: 기존 `test_*.py` 형식.

## 실행

```bash
cd deliverables
git -C ~/IdeaProjects/whale-erp-v2/whale-erp-front fetch origin main
git -C ~/IdeaProjects/whale-erp-v2/whale-erp-staff fetch origin main
.venv/bin/python build_screens.py --capture                # sources/screens/img · SOURCE.json 과 out/screens_visible_text.json 을 다시 만든다
.venv/bin/python build_screens.py --version 1.0 --draft    # 1단계(설명 행 없음)
.venv/bin/python build_screens.py --version 1.0            # 설명 행을 채운 뒤
.venv/bin/python test_build_screens.py
```

## 하지 않는 것

- 데모 원본을 고치는 일.
- 상태별 변형 이미지를 늘리는 일.
